# DOM accessibility profile

- Use meaningful landmarks only when their landmark meaning is true.
- Ensure one useful page heading and labeled controls.
- Keep focus visible, unobscured, and returned correctly after dialogs,
  navigation, and errors.
- Tie errors and status to programmatic names and announcements.
- Require keyboard reachability for every primary and recovery action.
- Check large text, zoom, and reflow without hiding content or forcing
  two-dimensional scrolling for ordinary app flows.

Use WCAG 2.2 expectations for focus visibility, target size, dragging
alternatives, and accessible authentication where applicable.
