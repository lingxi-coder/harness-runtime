# Compact progress alignment — Claude Code 2.1.261

> Historical baseline: the elapsed-only percentage described here is superseded
> by [phase-bounded estimated progress](compact-hybrid-progress.md). The binary
> evidence and original test results below document the earlier implementation.

The progress calculation and start/reset behavior now follow the official
Claude Code 2.1.261 binary inspected on 2026-09-05. The percentage is an elapsed-time
estimate, not a measurement of the fraction of input bytes compacted.

## Upstream evidence

- Binary SHA-256: `5efecaff231b798be3c66def9be54183623b328b80eaef17f93c43987024e82a`.
- Source byte offset: `177426284`.
- Extracted function, retained verbatim in the shared fixture:

```js
function Ro(n){let s=Math.max(0,n)/1000,c=1-Math.exp(-s/90);return Math.min(95,Math.round(c*100))}
```

The clock begins at summary generation (`compact_start`), after PreCompact hooks.
Repeated starts retain the original start time. Restoration retains that clock;
terminal outcomes stop the progress indicator. Examples: 4 seconds gives 4%,
90 seconds gives 63%, and the estimate caps at 95%.

`client-protocol/snapshots/compaction_progress_2_1_261.json` contains 299 outputs
generated by executing the extracted JavaScript, including negative elapsed time
and integer milliseconds around every rounding threshold. Rust, TypeScript,
Kotlin, and Swift tests consume this same fixture. This establishes output parity
for the tested inputs; the implementations in different languages are not claimed
to be byte-identical binaries.

## Implementation

- `platform-api`, `orchestrator`, and `client-adapter`: emit actual preparing,
  summarizing, restoring, complete, error, and cancelled lifecycle events.
- `client-protocol` and `clients/shared`: append `compaction_status` without
  changing existing variant ordinals or the legacy SDK stream sequence.
- `apps/bridge-server`: deliver manual compact events even without an active turn.
- `tui-core` and `tui`: start the percentage only at summarizing, preserve the
  clock across repeated phases, and retain the manual command guard until return.
- `clients/electron`: reduce lifecycle events into one compact row, preserve the
  clock across component remounts, enrich the row with completion metrics, and
  settle it on cancellation, error, or disconnect.
- `clients/android` and `clients/ios`: consume the same lifecycle, retain the
  summary clock, and stop the indicator on all terminal outcomes. iOS accepts
  connection-scoped compaction events outside an active turn.

The clients reuse existing progress components and terminal metrics. No new
dependencies were introduced. Completion without metrics no longer fabricates
zero-valued counters.
