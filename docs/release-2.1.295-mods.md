## Suggested implementation order and gates

1. **`onFailure` first.** Add the parsed policy to the Hook matcher/definition path, synthesize the block decision only for a failed hook configured with `onFailure: "block"`, preserve stderr/HTTP/spawn details, then run the public UserPromptSubmit path. Acceptance must assert the six Native pairings, zero model requests in the three block cases, successful CLI envelope with zero turns, and unchanged omitted-field behavior.
2. **`config.set` as a Host-mediated event.** Add `on("config.set")` registration only after the Native event shape and rewrite/deny semantics are captured. Keep it distinct from `$.config.set`. Dispatch it at the Host setter boundary before the actual persistence/live mutation, with source-backed key/value and tests for `/model`, `/fast`, and `/output-style`; retain the existing model-switch hooks.
3. **Options and reload.** Add the own-key special-name fixture and barrier-controlled save/reload race through `PluginRuntime.refresh`; assert the worker's registration sees the new values and correct enabled set. Keep property identity and option value separate from prototype validation.
4. **UI API and Button tree.** Probe `ui.notify` and Button child acceptance on each Native-supported surface. Then update worker and Host contracts together and retain the current press identity/epoch checks and LingXi renderers.
5. **Targeted regressions.** Add separate deep-input boundary tests, a rejecting-catch worker-epoch race, session-append Host/transcript assertions, and a background Hook env probe. These are not justified by reusing unrelated UI caps or intermediate worker results.
