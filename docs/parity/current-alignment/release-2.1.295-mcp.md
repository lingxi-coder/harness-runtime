# Claude Code 2.1.295 MCP release deltas

This note maps the MCP-specific 2.1.295 release changes to the current Harness
implementation and records the smallest acceptance checks for a follow-up
implementation batch. The comparison target is frozen at Claude Code 2.1.295;
no later release is in scope.

## Minimum acceptance for the next batches

### Batch A: pagination, output extensions, resource-list interrupt, external stop

1. **Repeated cursor:** Replay both 2.1.295 `mcp-pagination-295` receipts. For `tools/list`, `prompts/list`, and `resources/list`, assert exactly two requests, retention of the distinct page-0/page-1 entries, and no third request/error. Cover fallback and successful modern negotiation for tools aggregation; preserve existing cap behavior for a 20-page walk with distinct cursors. The source-identity test must compare decoded UTF-16 units rather than the raw JSON spelling.
2. **MIME suffixes:** Use the frozen binary's exact MIME-to-suffix table above to construct the next public runtime probe. Feed each MIME type through MCP output persistence, record the actual saved suffix, then verify Read returns the content. Keep the exact MIME inputs and output paths in a versioned receipt; the embedded source switch alone is not a runtime pass.
3. **Resource-list interrupt:** Hold an actual `resources/list` response open, interrupt the active turn through the same user-facing path exercised by Native, and record interruption output, JSON-RPC pending-call cleanup, and whether the connection remains usable. Candidate acceptance must finish the turn without waiting for the 60-second request deadline and must not report the call as completed.
4. **External stop:** Auto-background a long MCP call, stop it through the task-panel/connected-client path, and capture the next Native request/session rows and user-visible output. Assert one cancellation notice reaches Claude, the cancellation token fires, and a late RPC completion cannot resurrect the task. Keep a separate model-issued `TaskStop` case to ensure its current success result is not duplicated.

Candidate source/test seams are `crates/mcp/src/client.rs` and `crates/mcp/tests/mock_mcp.rs`; `crates/mcp/src/mcp_output_storage.rs` and `crates/tools/mcp/src/transform_result.rs`; `crates/tools/mcp/src/mcp_tool.rs` and `crates/orchestrator/src/turn_loop/tool_dispatch.rs`; and `crates/tasks/src/registry.rs` with `crates/core/src/host/task_notification.rs`. The final acceptance should cross the MCP client, tool, task/interrupt path, and actual turn boundary rather than stopping at helper-unit assertions.

### Batch B: reconnect lifecycle and typed server-error classification

1. **Headless reconnect:** Use a controlled remote MCP server to establish a connection, keep it alive beyond 15 seconds, then cause a post-connect drop and repeated failures. Capture connect timestamps and state transitions under 2.1.295. Exercise the same headless startup path as Native. Candidate assertions should cover continued retry after 15 seconds, increasing delays, a 30-second ceiling, reset after a stable connection, and no tight retry loop. Do not treat the existing desktop-only loop or its helper cap test as lifecycle evidence.
2. **Typed JSON-RPC error:** Keep a connection open while `subscriptions/listen` receives a JSON-RPC error response whose message includes a network-error name; assert the connection identity is unchanged and a subsequent request succeeds over that client. Compare with a genuine transport close and retain its reconnect coverage. A server error must not be classified solely by a network-looking message string.

Primary candidate seams are `crates/mcp/src/registry.rs`, `crates/mcp/src/registry/catalog_refresh.rs`, `crates/mcp/src/registry/tests/tests.rs`, and the host assembly that starts reconnect processing. Acceptance must distinguish a JSON-RPC `Remote(ResponseError)` from transport closure and test both under the same registered connection.

## Status

The official release note establishes that these six changes belong to 2.1.295. The code references above establish current candidate behavior. A 2.1.295 Native receipt now establishes repeated-cursor stopping and partial-page retention in fallback and modern discovery; the candidate implementation still needs its queued Cargo gate. The frozen binary's embedded switch establishes the exact MIME aliases/suffixes statically, while saved-file/Read behavior remains unprobed. The other four deltas still need Native behavior receipts. Production edits for those items remain frozen pending their approved write batches.
