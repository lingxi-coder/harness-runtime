# Native 2.1.295 PreToolUse and Stop `onFailure` probes

These four isolated public CLI runs compare an exit-1 command hook with `onFailure` omitted versus `onFailure:"block"` for `PreToolUse` and `Stop`. Each run uses the fixed 2.1.295 binary, a loopback-only Anthropic Messages stub, a dummy key, fresh HOME/config/cwd, disabled nonessential traffic, and a local `/bin/sh` hook. No upstream provider is contacted. Raw settings, hook stdin, request/SSE bytes, stdout/stderr, and session JSONL are retained per case; dynamic IDs and paths remain in those raw files.

For `PreToolUse`, the omitted-field run invoked the hook once, proceeded with Bash, wrote the fixed side-effect marker, and sent two provider requests. The `block` run also invoked the hook once and sent two requests, but did not create the Bash marker. Its actual model-facing tool result contains Native's `PreToolUse:Bash hook error` text, says it is blocking because `onFailure` is `"block"`, and includes the fixed hook stderr marker; inspect the raw session and second request for the complete message and run-specific command path.

For `Stop`, both settings invoked the exit-1 hook once, sent one provider request, and returned the first fixed assistant response successfully. The command script was prepared to exit 0 on a second call, but Native did not call it again in either run. This records behavior for this fixed single-failure Stop case; it does not establish a broader Stop-hook policy.
